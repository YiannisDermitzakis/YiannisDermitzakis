I've been mostly a quiet employee in the industry for many years. I was experimenting and building, small projects in my limited time, like many of the curious tech workers often do. 

As the AI productivity lever was raised in the recent years, I, too, felt the pull of what these little modern wonders can suddenly do. Big brothers of the artificial neural networks that fascinated me twenty years ago. I saw their promise then, and even got a scholarship to research them, but life happened and I found myself meddling with biochemical reactors instead. IT won me over again, and my career became building enterprise software (where I became a test-first convert) and more recently integration/delivery pipelines.

But right now the frontier is AI agents: getting them to behave unattended, in swarms, at scale, efficiently. So I got busy building.

**What's running**:

- **[frank](https://github.com/derio-net/frank)**: My first large-scale AI-native project. Build a self-hosted Cluster on heterogeneous hardware, running an immutable OS and do it fully declaratively, using best-of-breed technologies.
- **[blog.derio.net](https://blog.derio.net)**: a AI-generated blog that speaks with the voice of _Frank, the Talos Cluster_, documenting his Building process, his day-to-day Operations and the decisions that shaped him.
- **[vscode-launchpad](https://github.com/derio-net/vscode-launchpad)**: A small Tauri-packaged tool built spec-first with [openspec](https://github.com/Fission-AI/OpenSpec). Search and open any VS Code workspace from one dashboard, with a live monitor for active Claude Code sessions and a kill switch for the zombies. 
- **[blog-craft](https://github.com/derio-net/blog-craft)**: portable scaffolding and authoring skills for teaching blogs, built as Claude Code skills.

**What I'm currently focusing on:**

Most of my time goes to multi-agent workflows for building software. Spec-first, tight TDD, architecture I might iterate on, as it's now cheap. Testing software is my craft and I'm using it to pressure-test the agentic flow.

What I'm actually after is the layer under that: swarms that are trustworthy (reliable, secure, scalable enough to run autonomously) and composable (swappable workspaces, skills, secrets, tunable per agent). If that part's right, it shouldn't matter much what the agents are doing. It's code now, but it could as easily be support, security, or ops. 

I haven't found a system that does both well, so it seems I'll be building my own.
